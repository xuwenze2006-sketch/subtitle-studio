# 持续优化第六批：素材来源与启动响应

基线 `981da4f`。本批完成第 16、17 轮，审计、测试、审查与发布不另计轮数；下一次五轮反思仍在第 20 轮。

## 第 16 轮：保护素材实际消费生命周期

上批保护了单次哈希，但后续 FFmpeg 会重新打开素材。真实合成音频反例中，先算 440 Hz 原音哈希，准备回调改成 880 Hz 后，识别实际消费新音频，结果却登记旧哈希；恢复原音后可直接复用错误缓存。直接云端执行及丢失完成状态后的原始响应恢复均复现，同一预算请求无需再次发送。独立审计还在样片新建与恢复中复现了同类问题：清单属于原音，样片 PCM 却属于替换音频。

本轮将 Windows 共享读保护延长到完整任务与样片准备过程，从身份校验前覆盖探测、实际音频提取、后续预览和收尾。它只增加一个自有句柄，不复制完整媒体，也不逐片追加完整哈希；现有 identity、prepare、缓存、账本及输出恢复格式保持。正常读取、FFprobe/FFmpeg、重复继续及已有付费响应恢复仍可用；取消、异常和结束后释放保护。导入字幕仍解析已经核验的字节快照。独立双 worker 对照也确认取消及调度异常时，在途工作退出前保护仍然存在。

审查发现最初补丁将保护放在停止检查前，导致预先已停止且输入缺失/被占用时，文件异常抢在取消前返回。已用基线函数比较复现，恢复取消优先级并补回归；异常处理只覆盖取得保护，不把后续任意错误吞成初始取消。

这是关联正确性修复，不能宣传为识别质量或运行速度提升。代价是任务期间原素材不能被普通程序写入、替换或删除，需要编辑时先停止。本修复不能反向证明旧版本已生成缓存的真实来源，也不凭空补写历史证据。POSIX 保持原有空保护行为；恶意父目录重绑定和绕过 Windows 共享语义不在该保证中。

## 第 17 轮：启动校验移出任务控制锁

独立审计确认 `start()` 外层递归锁使内部已经分离的状态读取重新占用真实控制锁。同一个约 1 MB 临时状态文件、注入 250 ms 读取等待时，普通 `state()` 对照允许控制请求在 1 ms 内完成，`start()` 则使心跳、进度和停止请求等待约 274 ms。正常磁盘对照中启动中位约 20 ms；不能据此声称平常启动有显著倍数加速。目标是隔离慢读造成的连带阻塞。

采用锁外预检、最终锁内原子准入：预检使用选中项目快照读取状态与配置、检查动作并构建载荷；真正启动前重新核对关闭标记、选择代次、任务身份及配置代次。选择 A→B→A、另一任务在间隙启动又结束、另一启动先取得准入、账户/计价在预检期间成功保存、或服务已退出，都拒绝过期预检。只有通过最终检查才设置本次停止事件、标记 busy、保存摘要并启动工作线程。路径身份计算同样在预检外层锁之外完成。

同一脚本、文件与 250 ms 延迟条件下，修复后 progress/touch/stop 分别约 0.691/0.005/0.003 ms，在延迟读释放前完成。这是本机注入慢读时的控制请求隔离证据，不是普通磁盘提速或真实界面验收。

审查同时校正了最终路径身份的回归测试暂停点：携带项目令牌时，第二次调用属于状态显示，第三次才是载荷验证后的最终计算。校正后，通过只把最终计算移回锁内的反事实探针确认测试确实失败；当前实现通过。测试变化后中止并归档原完整运行，重新冻结全部源码与测试再跑，不沿用旧运行作为最终验证。现有摘要保存与线程启动临界区保持原样，不宣称启动过程中完全没有锁内文件系统操作。

最终准入成为并发胜负边界；尚未准入的预检没有占用运行任务，空闲停止仍返回未停止。该边界避免新增“预留任务”的恢复和取消状态机。已准入工作仍阻止空闲退出，线程启动失败保留原有收尾与提示。项目切换和云端停止标记的慢 I/O 是独立问题，本轮不扩大到这些路径。
