# 持续优化第三批：导出文件保护、响应边界与轮询隔离

基线为 `bc56fc2`。本批按三组独立问题计第 8–10 轮，导出同一文件边界的两处修补合并计一轮。所有复现使用临时目录、合成媒体与替代传输；没有真实提供商请求或历史账本变更。

## 第 8 轮：导出暂存不能覆盖输入，恢复不能误用变化中的成片

此前固定字幕暂存路径使用直接复制，ASS 转换直接写固定目标。NTFS 硬链接复现证明：暂存 SRT 若链接到源视频，真实复制会在第一个媒体命令前把 22 字节源文件改为 891 字节字幕。另一个真实读取复现中，既有成片在哈希读取 EOF 时被改写，恢复仍报告“已存在且校验一致”。

修复在独立临时文件中准备字幕和 ASS，再原子发布到原固定名称，保留旧编码参数与检查点身份。既有成片复用哈希前后检查文件代际，检测到读取期间变化则拒绝复用。暂存、转换失败和停止均应保留用户输入文件；不会为同一个恢复成片增加第二次完整哈希。

独立审查又证实 Windows 同尺寸写入后恢复 mtime 可以绕过普通 stat 五元组：此处 st_ctime 是创建时间，两种导出都曾误报成功。现追加原生文件句柄的 [FILE_BASIC_INFO.ChangeTime](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info) 观察，保持元数据与打开的文件身份对应；句柄始终关闭，查询失败或返回无效时间则保留文件并报错。真实 NTFS 回归覆盖原反例、原生查询失败、描述符释放和正常单次完整哈希。该检查面向并发文件变化，不构成对外部写入者的文件系统事务或持续锁定。

旧发布故障注入也按实际阶段收窄：字幕暂存开始复用复制助手后，原先全局替换 copyfileobj 的测试提前在字幕阶段报错。现在仅对 result.partial.mp4 的发布复制注入故障，保留原有不重复编码、检查点和文件保留断言，并增加“确实命中发布”的检查。首跑失败记录保留，不通过放宽断言取得通过。

另以本机真实 FFmpeg 8.1.1 对合成 SRT 执行独立临时 ASS 转换，格式推断、Unicode 路径和硬链接目标保护通过；此证据不代表真实视频编码、字幕视觉质量或 GPU 验收。

## 第 9 轮：Azure 成功与错误正文都必须有界读取

此前成功及 HTTPError 均执行无参数 `read()`。真实临时预算账本配合合成 5 MiB 正文，证明两条路径都会把整个响应读入并落盘，成功路径还会正常结算。

修复按 64 KiB 分块读取，实际正文最多 32 MiB，多读一字节用于判断超限，不能依赖服务声明的 Content-Length。该限额是应用资源边界，给长音频详细词记录留有余量，不是提供商配额声明。超限或读取失败按现有账本传输失败处理，保留 unknown 和预算预留，关闭响应，不保存不完整大正文、不自动重发。这一处理不把“拿到 HTTP 状态”误当作“已经取得可核实的完整结果”。

回归还覆盖第一次短读并非 EOF、错误/低报长度头，以及原生 HTTPResponse 被截断后仍返回合法 JSON 前缀的情形。默认 32 MiB + 1 字节的真实合成成功/错误正文均被拒绝，预算预留保持；恰好 32 MiB 的正常正文可结算并从缓存复用。

## 第 10 轮：项目路径慢读不再占住任务控制锁

此前 `/api/progress` 虽不加载字幕或凭据，但在主锁内调用 `Path.resolve()` 生成项目标识。事件门控真实路径解析后，“停止”操作在两秒测试期限内无法取得锁。问题来自锁的范围，并非需要提高轮询频率。

现在复用已有 detached read view，在主锁外解析路径。结束时核对选择版本，在锁内重新复制最新 job 和保存警告；选择改变时重读一次，持续改变则拒绝旧快照。项目标识继续使用原来的规范路径规则。回归覆盖慢读期间停止和进度更新、等待后的最新状态、项目切换、连续冲突和返回数据隔离。

单独的文件系统读取仍可能等待，本轮消除的是该轮询对任务控制锁的占用；不声称所有磁盘操作或云请求都已可以立即中断。

## 第二次五轮反思：第 6–10 轮是否有实际收益

有。五轮都先证明了具体失败：坏机器译文无法恢复、短暂共享冲突导致保存失败、暂存路径破坏输入或恢复误报、外部正文无界读取、慢路径解析阻塞任务控制。它们直接影响已有结果保护、重试成本和停止响应，没有通过增加新功能或改名凑轮数。

维护成本主要是并发和恢复边界的回归测试。实现复用已有原子 I/O、预算状态机和 detached view，没有新增服务、依赖或持久化格式。导出同一边界的两处修补合并计轮，测试夹具维护、审查、发布均不另计。

验证也显示测试总数不能替代针对性反例：初跑 1,235 项通过后，审查仍找到了 Windows 时间恢复缺口。这次追加了窄范围原生元数据查询和真实回归，而没有把初跑通过当成发布依据。新增平台代码的成本是两次轻量元数据观察，不增加整片扫描；最终回归和复核重新执行。

仍有明确边界：免费翻译逐字节慢响应可以超过注释所述 15 秒，停止期间仍占用翻译队列。离线 socketpair 已复现；本批先收敛上述三个边界，下一轮应独立处理实际总截止和取消，避免用残留后台读取线程掩盖问题。付费传输若扩展同类取消，仍须保守保留可能已计费请求的预留。没有真实云服务、原生 GUI 或翻译语义质量的验收证据。
