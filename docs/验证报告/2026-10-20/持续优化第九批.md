# 持续优化第九批：损坏项目的服务接续

基线为 `d247aea`。本批完成第 22 轮，累计 22 轮；下次五轮反思仍在第 25 轮。本轮之外的字幕保存和前端回执审计未发现新确证问题，不计产品优化轮数。

## 问题与实际反例

恢复上次任务时，若选中的 `state.json` 含 `{"config":null}`，控制器读取状态会抛出属性错误，真实 `/api/state` 直接断开连接，没有 HTTP 错误正文。界面因此把本机服务标记为离线，禁用载入、新建等操作；再次启动时，既有服务探测也会拒绝重新打开仍在运行的进程。

最小复现使用临时项目、合成素材字节和自己的确切回环地址；未使用用户任务、真实凭据或浏览器存储。原文件在复现前后保持相同字节。服务的进度接口仍可读，确认故障发生在项目状态组装，而不是服务进程退出。

## 修复与保留的能力

服务连接信息、账户公开状态和项目详情分开组装。用于状态展示的项目 JSON 严格区分损坏内容与未创建的新项目；遇到读取错误或不符合预期的结构时，返回明确的 `project_error`，不在读取时自动修复或覆盖原目录。

界面继续保持已连接，显示“当前项目需要检查”及服务端说明。项目有问题时，禁止新的识别、准备、样片、整片和视频导出后台任务；正在运行时保留停止权限。最终返回状态前仍刷新实际任务，防止读取期间任务变化重新放行处理，也防止旧错误覆盖刚切换的健康项目。

修复原文件后可重新读取；也可以载入其他健康任务或新建任务。合法的既有字幕读取和独立版本保存继续沿用原校验，便于抢救工作。本轮没有冻结所有非启动入口，也不保证任意损坏元数据都能预览；项目状态可达不等于损坏文件已修复。

原来宽容读取的其他调用保留默认行为。四个既有测试文件中的慢读替身只调整为透传新增的严格读取参数，事件门和断言均保留；没有通过删除并发检查来获得全绿。
