# 持续优化第十批：损坏预览与未保存校对恢复

基线：`52e0e70`。本批完成 **1 轮**，累计 **23 轮**；下一次五轮反思在第 25 轮。后端错误处理和前端草稿逃生入口共同解决同一恢复流程，不拆分计轮。

## 第 23 轮：预览失败时保留真实人工状态与处理入口

实际反例：恢复的本地项目 `state.json` 中 `config` 为 null、数组、数字或字符串时，状态接口仍能报告项目错误，但预览和字幕下载会因无类型检查的 `config.get` 抛出 AttributeError，HTTP 连接直接断开。相同恢复流程中，已有未保存草稿、离开校对再返回而预览失败时，编辑器与草稿恢复区都被隐藏；任务切换仍正确阻止未保存输入，用户却无法查看或明确放弃它。

进一步复现：已有人工校对记录时，底层 identity、duration_ms 缺失或状态 JSON 损坏，会跳过人工覆盖层读取而静默展示机器字幕；同一结果的下载却正确拒绝无效绑定。此处不是人工记录已被删除，而是预览错误表达了它的状态。

修复：

- 仅在实际使用本地语言配置时验证对象类型，通过既有 HTTP 错误通路返回 JSON 400，不扩大通用异常捕获，也不按 `project_error` 一律封锁字幕读取。
- 已有人工校对记录独立触发原来的绑定验证。底层状态或任一机器字幕缺失时，显示人工记录冲突；不自动改写原文件、重建人工记录或伪造有效修订。无人工记录且只读原字幕不依赖异常身份时，继续保留原字幕抢救能力。
- 预览失败或不支持人工核对时，仍显示保留草稿的只读原文、译文、时间和备注，允许复制、重试或明确放弃。首次读取失败只恢复当前项目与当前请求片段的本机草稿，不推断服务器修订；重试后保留原基准并按既有规则显示版本冲突。
- 放弃操作继续使用已有本机草稿 CAS；其他窗口的新草稿不被清除。任一当前会话提交尚未结束时，按钮与执行函数均阻止放弃。未自动提交、放弃或替用户作整片验收。

## 实际浏览器与边界

使用内置浏览器加载本轮实际构建产物，通过真实本机 HTTP 服务操作临时合成项目：输入译文和备注、离开预览、损坏项目配置、返回失败预览，确认草稿只读展示；新建任务仍提示先处理草稿；修复配置后刷新，原输入继续出现在编辑器；再次损坏后明确放弃输入，成功载入另一正常临时任务。保存浏览器状态与恢复入口截图，关闭临时页和测试服务，确认临时目录已清理。

这是实际浏览器恢复流程验证，不是原生桌面启动、真实素材播放或云提供商验收；合成媒体字节本身不可播放。未访问用户项目、真实账号或付费服务。

仍不宣称任意损坏元数据都已修复，或冷启动可以自动发现每个历史片段的草稿；首次失败恢复只查当前项目和已知请求片段。人工记录绑定冲突继续沿用现有展示与下载拒绝语义，本轮不会把机器字幕宣称为已恢复的人工结果。

本轮有可复现的恢复死角、静默人工状态遗漏及真实浏览器收益。新增分支和回归测试带来维护成本，未借此增加存储格式、自动迁移或全局读取封锁。
