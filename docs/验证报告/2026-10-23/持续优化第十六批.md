# 持续优化第十六批：原文预览与资格检查

基线 `2b455278167212da18b8ed960387bbd5a56f6de0`。本批完成第32轮产品优化；上次五轮反思30，下次35。原文MP4已在上一批公开发布；本批保持操作步骤、记录格式和实际导出契约。

## 问题和结果

原文项目没有任何导出回执时，查询当前成片仍先完整加载校对并生成交付SRT，然后才得知成片不存在。整个预览因此完整加载校对3遍。状态轮询的资格布尔值也生成了从未使用的字幕和快照绑定。

现在先在包含性/链接保护下读取固定成片回执，缺失、损坏或明显非候选直接返回。候选仍执行原来完整的输入、所有权、快照、发布证明和源/成片摘要检查。资格布尔查询在所有准入检查完成后才跳过交付构造，真正导出和候选查询的完整绑定不变。没有新增缓存、依赖或前端改动，所有内容读取继续位于脱离主控制锁的请求视图。

## 证据

新模块9个测试在实现前复现10个预期断言失败（含损坏回执子例），其余保护性场景通过。实现后，新增、既有原文导出及Studio相关共53项通过。覆盖无回执/损坏或非候选回执、不渲染资格字幕/快照路径、无效当前条目、丢失人工历史、有效候选快照损坏、真实导出完整绑定及后续请求外部修改。

相同离线探针在100、2,000、10,000句以及有/无人工记录共6组项目中执行24种操作，修改前后能力和无成片结果一致：

| 操作 | 修改前 | 修改后 |
| --- | --- | --- |
| 没有导出时的预览完整校对加载 | 3遍 | 2遍 |
| 10,000句预览的条目验证 | 30,000句 | 20,000句 |
| 该预览中的完整SRT渲染 | 2遍 | 0遍 |
| 没有回执时当前视频查询的校对加载 | 1遍 | 0遍 |
| 状态/资格查询的交付SRT渲染 | 1遍 | 0遍 |

这是确定的工作量减少，不代表消除了所有重复校对。实际当前校对验证仍存在，有人工记录时状态读取仍做两遍。没有跨请求资格缓存，外部文件变化不会因上次成功而被隐藏。全组内容读取均未持主控制锁；页面原有空闲轮询约4.5秒，运行中使用轻量进度请求，本批不调整轮询频率。

计时存在显著主机负载波动，完整最小值/中位数/最大值均保留。不以两组中位数推出固定加速倍数、整体吞吐提升或费用节省。优化前profile主要成本为重复逐句校验，媒体源/分段扫描并不是此次轮询瓶颈；既有视频哈希缓存已能在相同文件代际下复用，因此没有另加视频缓存。

对上一批自建合成双音轨项目做当前代码只读核对：实际CPU成片仍正确返回，成片SHA与上一批独立媒体验收一致，相关50个文件的内容和修改时间未变；零重新编码、零提供商请求。这仅证明既有真实成片读取兼容，不冒称新一轮媒体/画面、真实长片、原生GUI或QSV验收。
