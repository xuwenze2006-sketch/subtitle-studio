# 持续优化第十五批：原文 MP4 交付

基线 `03be4e06018ff63125b1e1d88ab4228bfe64eb35`。按用户要求优先补齐原文 MP4，验证后上传 GitHub。本批为**第31轮**产品优化；上次反思30，下次35。测试、审查和验证工具调整不计产品轮次。

## 结果和使用流程

完整本地原文任务现在可在工作台或校对页点击“直接导出草稿 MP4”，压入当前已保存的原文字幕。无需开启翻译、补做双语验收或重新识别。视频明确标为未审核草稿，保留原视频、原分辨率/帧率及全部音轨，不改变检查数量或最终验收状态。

输出位于 `项目/导出/原文视频/`，带原文、输入标识和未审核草稿名称。更改保存修订会保留旧视频并生成独立新版；相同绑定再次导出可复用已经通过校验的文件或编码检查点。没有测量真实长片耗时或货币节省，不据合成小视频宣传总体提速。

## 实现和保护

从既有 `media_export` 抽取共享渲染，保留原云端文件位置、绑定、编码参数及验收契约。新增 `source_video_export` 负责独立本地资格和回执，不伪造 campaign/审核记录，不增加依赖。

- 状态完整之外，还核验本地引擎、关闭翻译、项目/来源路径、语言/时长、所有分段来源和内容证明。实际导出全程持有原视频稳定读保护并重新哈希，沿用项目锁。
- 当前有效原文 SRT 可含合法外部人工修改，沿用 v2 原文快照；不是把旧机器合并内容重新盖回用户字幕。待发布、待合并或损坏记录继续拒绝。
- 原文绑定明确包含来源、字幕、生成状态、修订及实际人工记录存在性。固定所有权记录保留“曾有实际人工记录”的事实；人工记录和顶层视频回执丢失时，不能静默退回机器原文，包括空 patch 记录。
- 每个输入键独立工作目录及回执，顶层指向当前结果。发布或最后登记失败可按确定输入键恢复，不根据目录时间猜测最新版本；未知同名文件不覆盖，取消/旧视频/部分编码继续保留。
- 复用完整媒体验证与逐音轨压缩数据校验。MP4 不兼容音频明确失败，不偷偷有损转码；链接/联接及可能截断外部文件的硬链接日志被拒绝。
- 两布局严格消费明确原文导出能力。未保存、等待保存、恢复草稿、项目/修订冲突和运行中禁止导出。紧凑保存回执直接更新能力并撤下旧视频，不额外读取整份预览，不自动播放。

当前成片入口核对来源、字幕/状态、快照、发布证明及视频字节。编辑后旧文件保留，播放/下载入口撤下。已知所有权证据全部被外部删除时，无法由目录顺序推断丢失的历史；UI 摘要缓存仍是优化，实际导出始终重新核验来源。

## 真实本地验收

使用上一批保留的清晰合成英语视频，添加第二条独立音轨，在新的隔离项目中由真实 Whisper small 识别一次，生成4句。实际浏览器保存原文和开始时间100 ms，再通过新前端、正常 Studio worker/HTTP 与真实 FFmpeg CPU 导出。

独立 FFmpeg/ffprobe 检查两版输出：640×360、帧率/帧数与输入一致，时长18.2秒，两条音轨的顺序、编码、采样率、声道、语言/default/forced及压缩数据哈希保持一致。认证下载与文件逐字节匹配。在各版2秒画面中分别实际看到“Original subtitles are now exported to MP4.”和“A second original subtitle revision is preserved.”，确认文字已经烧录到视频像素。

关闭并重启服务后，从真实界面重复导出同一修订；明确报告无需重复压制，视频、部分编码、编码日志和编码检查点摘要及修改时间未变。随后在新界面修改原文：未保存时导出被禁用；保存回执撤下旧播放入口，导出生成另一份视频，旧视频字节和时间不变。

共1次真实识别、3次明确导出请求（2次实际编码、1次缓存复用）。26项运行证据检查通过，原视频及原机器字幕/日志/流水线状态完整保留。父进程禁止外部网络，三个实际导出 worker 均加载拒绝网络的验证保护，零网络尝试；账户查询置空以保护真实凭据，自建服务全部退出。未启动原生播放器。

只验收合成清晰英语、短视频和CPU；未冒称真实长片/嘈杂日语素材、QSV、原生桌面启动/播放器或真实云端账户验收。

## 回归、审查及如实保留的失败

新后端原文导出33项、Studio集成11项、前端28项。测试先复现缺口及提交/快照/记录损坏等边界，再实现。后端相关218项（217通过、1项原有Windows权限跳过）、Studio相关39项及前端定向94项通过。独立最终审查未发现具体阻塞问题；额外真实Windows深路径探测在最长333字符编码路径、388字符发布路径成功，并核对摘要，未复现MAX_PATH阻塞。

冻结214个源码、测试及前端配置文件。生产构建和26次回环HTTP通过，真实提供商请求为零，最终源码与审查摘要保持一致。

本机完整回归没有把失败记成通过：

- 首轮后端1503项，1499通过、1失败、3项环境跳过。既有 `test_deadline_also_covers_blocked_dns_and_connect` 的connect子例在测试注入的0.6秒截止时尚未写入阶段就绪标记；原样单独重跑通过，未改变生产15秒期限或测试0.6秒期限。
- 首轮前端480项，477通过、3项超时：`AppProjectRecovery`的健康任务恢复、`PreviewLocator`的筛选后定位、`PreviewSourceOnlyReview`的原文纠错检查；同一源码、原5秒时限下对应3文件17项通过。
- 降为单进程的第二轮前端480项，478通过、2失败：`App.test`的离开/撤回草稿保护在等编辑入口时失败，`AppRecovery`的恢复后保存超时。原样定向3项通过（含同一恢复动作的保存/放弃分支），未增加时限。两轮失败项不同；并行负载是推测，未证明精确的系统根因。

原始日志、失败时冻结摘要与定向结果均保留，未修改这些旧测试或相关程序来迎合本轮门禁。本机后端在无本轮前端套件同时执行时再做完整复核，最终结果另见发布回执；不靠反复全套重跑直到偶然绿灯来隐去原失败。

最终完整门禁使用独立 GitHub Windows 运行器：验证分支先运行同一提交的后端、HTTP、全部前端、生产构建及内置资源一致性；成功后才普通快进公开main，再确认main的同提交检查。若门禁失败，保留分支与证据继续修复，不把“已上传验证分支”等同“主分支已发布”。

## 收尾和成本边界

只提交本批明确的源码、测试、内置构建和文档，媒体、临时项目、截图、日志及凭据不上传。允许路径与密钥/媒体扫描通过后普通推送，保留现有公开及私有历史。主工作区仅在远端同提交检查成功且仍干净时快进同步。

本轮复用渲染及紧凑回执，减少工具切换、重复识别和相同输入重复编码；新增原文资格/所有权/视频回执也增加维护成本。更改非画面修订信息仍可能生成独立编码版本；没有宣称所有元数据变化均可零成本复用。累计31轮，下次五轮反思35，后续以实际流程价值判断，不以新增测试数充当产品收益。
