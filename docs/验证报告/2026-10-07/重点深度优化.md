## 问题与修复

| 问题 | 修复与回归证据 |
| --- | --- |
| 长字幕播放仍反复查找当前校对句、是否有未检查条目和已完成回放句 | 缓存只随字幕数组和句身份变化的结果。20,000 条、最后一句校对草稿的夹具中，单次播放更新原有约 60,000 次 `some/findIndex` 条目访问降为 0；备注编辑也不重扫。数据更新重新计算，无 ID 回放仍按原位置处理。该数字是指定查找探针，不代表整个页面所有操作的耗时。 |
| 整片验收提交属于页面，切走后可能重复写入或丢失回执 | 复用共享会话提交记录，保持 pending、成功、冲突和失败；等待时阻止任务切换并保护关闭提醒。写入成功后的预览/状态读取失败保留成功事实。回执绑定原页面读取身份及版本，旧读取不能覆盖新页面较新字幕。 |
| 打开导出视频前，完整文件校验持有任务控制锁 | 文件读取与哈希移入独立项目视图；启动系统应用前重新检查项目选择。用受控的真实 SHA 读取验证四种视频/目录目标校验期间进度和停止可响应；切换项目后不会启动旧目标。系统启动动作由测试替代。 |
| socket 空闲超时可被持续滴入请求字节延长，耗尽处理名额 | 请求行/请求头和正文分别使用绝对读取期限，每次底层读取重新计算剩余时间；不添加计时线程，不限制控制器执行或媒体写入。真实回环滴入测试证明超期释放、名额恢复；长业务和独立读取阶段仍通过。 |
| 声明较长正文却在合法短 JSON 后断开，原先仍执行操作 | 正文长度必须完整匹配声明，短 JSON 也返回错误，停止动作不执行。 |
| 空闲退出判断与新任务准入之间存在竞争 | 认证 touch、退出认领和启动共用主锁；认领退出后，已排队请求也不能启动工作线程。用实际退出循环及两个锁顺序验证，待落盘记录仍阻止退出。 |
| 确定尚未发送的请求恢复/429 重试时，响应位置被占用却仍先发送 | 初次准入、恢复和发送标记前检查原路径与规范路径，用 `lstat` 区分占用、访问错误和非目录父路径。拒绝时保留账本及原文件；成功/已收到/未知提交恢复保持既有规则。 |
| 旧 Azure 适配器允许响应副本覆盖输入音频或其他付费响应 | 规范化路径后，在账本准入前拒绝输入、账本/锁及其他共享响应目标。原问题可将 32,046 字节的临时 WAV 覆盖为 45 字节 JSON；新回归保护文件内容且不调用传输。 |

每组修复先记录失败，再执行最小修复和回归。前端读取时序与后端传输/打开结果边界另经独立代理复核，未发现阻塞意见。
