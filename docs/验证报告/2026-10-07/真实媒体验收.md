# 2026-10-07 本机真实媒体验收

本轮使用真实 FFmpeg 编码、压制、解码和音轨内容校验，素材全部由离线工具合成。没有读取或修改个人素材，没有请求云端识别或翻译。以下结果证明本次环境和短片路径的行为；不能外推为任意长片、云端识别准确率或人工听看通过。

## 工具与运行方法

新增 `tests/media_fixtures.py`、`tests/media_acceptance.py` 和 `tests/test_media_acceptance.py`。夹具、JSON、媒体、截图及进程日志保留在 Git 忽略的 `验证样例/`，命令行拒绝把输出写到该目录以外或覆盖已有 campaign；复用夹具时核对源哈希和路径，每轮验收创建独立 `run-*` 子目录。

```powershell
python -m unittest discover -s tests -p test_media_acceptance.py -v
python tests/media_acceptance.py --fixtures-only
python tests/media_acceptance.py --fixtures "验证样例/media-acceptance-1791364151436788400/fixtures.json" --encoders cpu,qsv
python tests/media_acceptance.py --fixtures "验证样例/media-acceptance-1791364151436788400/fixtures.json" --mid-encode-cancel-only
```

也可以省略 `--fixtures` 一次生成并验收，或使用 `--encoders cpu` 仅检验 CPU。`--tones` 明确改用诊断音，默认使用 Windows 离线语音，不访问语音服务。编码方式由生产入口 `cloud_workflow.export_video(..., encoder=...)` 选择；验收同时检查成片 binding 与编码检查点的真实 FFmpeg 参数。夹具进程和取帧调用有期限，导出有 120 秒停止看门狗。

工具的 10 个低负载契约测试已逐步观察到缺失实现的失败，再实现并通过，覆盖三段 cue 重建、真实 `sample_state_evidence` 校验、浏览器项目载入、禁止覆盖、路径逃逸、音轨丢失、时长偏移、字幕像素缺失、显式 CPU 选择被悄悄换成 QSV，以及必须见到正进度和活跃编码进程才停止的条件。真实媒体集成是单独显式运行的命令，不加入日常离线回归的高负载部分。

## 取消、恢复与检查点

CPU 和 QSV 各执行一次真实编码完成后的停止测试。工具观察 `encoding-checkpoint.json` 的 `encoded` 记录已经写入，随后注入停止信号，生产入口抛出 `Cancelled`。停止时保留真实编码文件及严格输入/字幕/编码器身份检查点，尚未登记发布成片。

两种编码的所有检查均通过：

- 检查点哈希等于保留编码文件哈希。
- 恢复时调用生产导出入口，重编码调用数均为 **0**；成功发布成片的哈希等于停止前编码文件哈希。
- 再次导出同一已完成结果，`runner.run_process` 调用数均为 **0**，成片哈希不变。该计数覆盖字幕转换、编码和抽段解码；环境编码器短探测及 ffprobe 仍通过 `capture_process` 运行，不宣称没有任何进程启动。

上述结果是“编码完成并验证后、发布前取消”的确定性集成证据。它复用的是已完成且哈希/身份校验通过的编码文件。

另以 `--mid-encode-cancel-only` 定向验证了真正编码中的停止，没有重复前面的六项输出。工具用现有合成 H.264 片段直接循环成约 72 秒、6,843,236 字节的测试输入；保持生产 FFmpeg 参数和进度轮询原样，不注入慢速编码参数。

实际停止观测为 `phase=encoding`、`encoded_seconds=8.125`、进度约 11.28%，当时 FFmpeg PID 为 22756，`poll()` 确认进程仍在运行。工具设置停止信号后生产入口抛出 `Cancelled`，进程随后已退出。以下 14 项检查全部通过：

- 停止时编码检查点仍为 `encoding`，不会被误认成已完成文件；没有登记成片路径，也没有发布审核版 MP4。
- 中断文件保留 524,336 字节，SHA-256 为 `caadee8455713e15c797004de8ec65f0f501c044a6ee2ca25b07ab537a48b59f`。
- 原字幕、片段响应、state 及输入文件哈希在停止和恢复后均不变。
- 恢复实际执行 **1 次完整 CPU 编码**；中断文件归档后仍保留原完整哈希，最终成片时长在 72 秒 ±250 ms 内，发布文件哈希与 campaign 记录一致。

这条恢复路径从头重新编码，不宣称从中断帧续接，也不复用未完成编码文件。
