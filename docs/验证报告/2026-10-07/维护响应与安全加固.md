# 维护、响应与安全加固（2026-10-07）

## 本轮范围

在当前有未提交改动的版本上修复已复现的问题，保留已有功能、字幕、人工记录和费用数据。未提交 Git、未调用识别或翻译服务。源码与旧前端构建快照位于 `output/验证记录/2026-10-07/maintenance-hardening/before-source.zip`；同目录 `turn-only.patch` 可独立查看本轮差异。

## 修复内容

| 方面 | 问题与结果 |
| --- | --- |
| 静态文件安全 | Windows UNC、设备名、盘符、反斜杠、ADS 和目录穿越在文件系统解析前拒绝，随后继续验证解析后的路径归属。UNC 复现使用解析器拦截，没有连接远端 SMB。 |
| HTTP 资源控制 | 提取 `studio_http.py`，最多 32 个请求处理线程，socket 空闲超时 15 秒，超额立即关闭连接；正常结束、异常和启动失败都回收名额。这个网络超时不会取消耗时业务。 |
| 异常输入恢复 | 非 ASCII 会话令牌返回拒绝；NaN/Infinity 等坏费率不再使整个状态接口无法序列化，界面显示配置错误，原配置仍无法通过云端运行条件。 |
| 首次连接 | 本机会话也有覆盖响应头和正文的 15 秒截止时间，保留入口 token 供手动重连，不自动重复提交业务写请求。提示浮层避开连接栏。 |
| 下载与校对并发 | 下载、版本保存独立跟踪回执，保存校对不会让按钮一直禁用；旧项目或片段的回执不能清除新请求状态。 |
| 保存后刷新 | 保存或验收已经成功时，后续状态刷新失败会准确提示并保留成功事实；可以只读重试。新操作开始即使旧刷新失效，避免迟到失败覆盖新结果。 |
| 后台异常退出 | 调度异常先通知工作线程停止，再等待清理结束；内部停止不冒充用户取消，仍核验和恢复已完成结果，保留最初错误。 |
| 取消完整性检查 | 整片、样片及样片缓存复用都传递停止信号，并在发布完成状态前再检查；取消后不继续扫描剩余证据或宣告本次完成。 |
| Windows 进程清理 | 明确记录当前作用域异常，避免 CPU 编码回退时将子进程清理失败错误附到已处理的旧异常而吞掉。 |
| 回归稳定性 | 修正旧定位测试等待条件：等待输入框可用再输入，避免初始异步加载时丢字。没有放宽产品校验或修改仓库默认测试时限。 |

## 数据保护与使用
