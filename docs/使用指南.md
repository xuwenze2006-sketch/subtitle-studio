# 字幕工坊使用指南

安装及启动请先阅读 [README](../README.md)。本页说明任务恢复、人工校对及导出的具体行为；标有日期的性能数字只代表当时的本机测量。

## 字幕语言组合

新建任务后，在“字幕语言”中分别选择原音语言与翻译目标。支持日语、英语、中文之间的六种双语搭配，例如英中、中英、日英、英日、中日、日中。本地识别还可选择自动检测原音，关闭“生成译文与双语字幕”时只制作原文字幕。云端完整流程按选定组合识别、翻译、审核和导出；硅基流动试听仍自动检测原音，尚不提供已验证的同步字幕。

语言组合随任务保存，载入后会恢复并锁定；更换语言请新建任务，避免误用已有识别或译文缓存。未记录语言的旧云端任务仍按日语→中文读取。英文、日文译文分别保存为 `英文草稿.srt`、`日文草稿.srt`，预览、下载和版本记录会显示实际语言。整片生成完整即可直接压制未审核草稿，审核版另需完成人工验收；成片名称随译文语言变化。

## 人工校对与整片验收

在工作台点击“进入校对台”，选中字幕旁的“编辑”按钮，可以修改原文、译文、起止时间和备注。先播放该句核对原声，再按“已核对本句”；听不清或仍有错误的内容按“标记疑点”。播放本身不算检查。通过筛选和“下一条未检查”继续，已保存的检查状态会在重新打开项目后恢复。

编辑文字或时间会将该句恢复为未检查；改了原文时，原译文会标为待确认，需要校正译文或明确确认后才能标为已检查。保存只写本机记录，不调用翻译服务。尚未保存的输入会提示；另一窗口已经保存时，本窗口须先载入最新版本并核对，避免相互覆盖。

本句保存期间切换工作台、校对台或暂时打开其他页面，会继续等待原提交，返回后消费同一份保存回执，不重复提交。成功回执只确认该次提交的内容，后来的修改仍保留为未保存输入；失败则保留输入并提示。尚未保存或保存中的本句会暂停字幕下载和“保存字幕版本”，避免把旧磁盘内容误认为当前输入。刷新会重新读取实际项目文件，不会自动重发此前的保存。

修改后会立即尝试在当前浏览器保存本机草稿。再次打开同一项目、片段时恢复输入并提示；草稿不算正式校对记录，不用于字幕下载或视频导出。正式版本已经变化时保留草稿并阻止旧版本保存，需要明确载入最新版本再核对。浏览器存储被禁用、已满或另一窗口更新草稿时会提示，输入和正式保存入口仍保留。

草稿只保存项目身份、本句文字/时间/备注/检查状态及原修订，不保存 Key 或会话令牌；默认保留 7 天、最多 30 个项目片段、合计 1 MiB。清除浏览器数据、更换浏览器或手动指定另一端口会隔离或删除这些草稿。默认服务重启优先复用上次端口；端口被占用时提示旧地址草稿暂不可读。重要修改请正式保存，不能把浏览器草稿当作备份。

其他窗口切换了服务当前项目时，原窗口会保留校对输入，并提供“恢复原校对任务”入口；只允许恢复该稿原本绑定的素材、项目和身份，回执或后续状态不匹配时继续保留并提示。服务仍在运行另一个任务时展示其实际进度，停止后才能恢复。仅提交“已核对本句”也会在等待回执期间提醒关闭或刷新，并阻止切换任务；收到成功回执后解除提醒，不自动重复提交。

人工修订单独保存在所选整片或样片目录的 `人工校对/校对记录.json`，机器生成文件、分段证据和费用记录保持原样。下载、保存字幕版本和 MP4 压制会采用同一修订版本的原文、译文和双语字幕；快照保存在 `人工校对/版本/`。原始字幕或项目识别信息被外部改动时，程序保留人工记录并提示冲突，不擅自合并。暂不支持新增、删除、拆分或合并字幕条目。

已完整生成的整片草稿可以直接人工抽检，不需要补跑已跳过的样片。至少明确检查 20 句（不足 20 句则全部），处理完所有**人工标记的疑点**和待确认译文后，勾选验收确认并提交。自动提示是选取复核内容的参考，请优先检查开头、中间、结尾和自动提示处；20 句门槛只是抽检要求，不代表整片逐句校对或准确率保证。通过后可导出审核版 MP4，之后修改字幕需重新验收。

需要先观看带字幕的整片时，在工作台或字幕校对页点击“直接导出草稿 MP4”，无需人工检查或勾选验收。它使用当前已保存的字幕（包括人工修订），文件名带“未审核草稿”，项目仍保留原审核状态。原视频和审核版保持不变；编码、音频与时长检查照常进行，不产生识别或翻译费用。草稿路径与字幕绑定，修改字幕后不能把旧草稿当作当前版本；如果同名文件已有不同内容，程序保留旧文件并提示先另存。

顶部“本机环境与视频导出”自动检查 Python、Tk/Tcl、FFmpeg、ffprobe、subtitles/libass、本地识别文件和实际短编码能力，可手动重新检查。检查不调用云端服务，也不会下载模型；模型文件存在不等于已加载或识别质量通过。整体媒体探测预算 20 秒、每个子进程最多 5 秒。

编码方式默认“自动选择”：实际探测 Intel QSV 可运行才选 QSV，否则探测 CPU `libx264`；也可明确指定一种。草稿用 `veryfast`，审核版用 `fast`，保持原分辨率、帧率和音轨；QSV 使用质量参数 `20`，CPU 使用 CRF `20`，二者不是等画质保证。编码途中失败不会自动换编码器再跑一次。编码方式写入完整性绑定，明确切换方式不能认领旧方式的结果。命令行 `python -m subtitle_pipeline.cloud_workflow export` 或 `export-draft` 同样支持 `--encoder auto|qsv|cpu`。工作台显示编码百分比、倍速、预计剩余时间，并区分编码、媒体校验、保存阶段。

新导出在编码成功后保存输入、字幕样式、编码参数和视频哈希绑定的检查点。后续媒体校验或文件复制失败时，重试复用一致的编码结果；成片已经保存但项目记录写入失败时，可补齐记录。源素材、字幕、编码参数或编码文件变化会使检查点失效；无法证明来源的旧版临时 MP4 不自动复用，再次编码前移入 `导出/草稿视频/保留的编码/`（审核版位于 `导出/保留的编码/`）。编码中途停止暂不支持从某一视频帧续接。MKV 未提供总帧数时不再据此报错，仍检查分辨率、帧率、时长、音轨和三个位置的解码。

编码成功且成片完整 SHA 已保存后，在后续源视频复核阶段停止或中断，可以恢复该阶段而不重新压制；恢复时重新核对素材、字幕、参数、源文件状态和源/成片完整 SHA，并照常执行首次媒体检查。成片 SHA 尚未完成时仍不能安全复用，保留文件后重新编码。已经完成的编码检查点在复用前也会重新检查输入内容，不能用过期媒体记录跳过变化检查。

媒体检查已通过而成片复制中断时，重试会复用与当前编码文件一致的检查记录，不重复扫描音轨和解码三个位置。源视频、编码文件和目标副本仍检查完整 SHA；检查记录缺失、损坏或输入变化时重新验证。停止信号覆盖媒体探测、音轨校验、大文件哈希与复制；已完成的编码保留，正在写入的发布副本清理。单次磁盘读写、同步刷盘和系统进程终止仍受操作系统响应时间影响。

成片已保存、最终验证或项目记录仍在写入时收到停止，任务返回“已取消”，不会同时报告导出完成。已成功保存的成片和记录保留，再次导出时重新核对后复用或补齐记录，无需重复编码或复制。最终 JSON 记录仍使用现有有限文件占用重试，停止在该次写入返回后检查；不承诺立即中断系统文件操作。

导出准备中的完整生成校验也接收本次停止信号：实际读取源文件及片段证据的完整 SHA 时，每块最多 1 MiB，并在读取前后检查停止；逐段检查和返回完整状态前再次检查。取消不会变成普通“字幕不完整”，也不会继续启动媒体准备。所有来源和片段内容校验仍保留，单次系统读取或文本解析的响应时间受当前操作影响。

导出时，项目和识别记录指向同一实际路径的源文件，只在生成校验阶段完整读取一次，同时核对两份来源哈希；不同路径仍分别读取。编码完成后保留另一次完整源文件复核。已保存成片复用前也会重新读取当前源内容，不能用文件大小或修改时间替代。这里减少的是重复读取次数，并非整片导出速度保证。

Windows 在发布副本或清理临时文件时短暂返回文件占用/访问冲突，会有限重试同一次文件操作，最多 6 次、合计约 0.62 秒退避；停止可打断退避，不重复复制或编码。目标文件已存在时不会覆盖。若临时文件仍被占用，保留原导出错误并报告待清理路径，清理或日志错误不会遮蔽原失败。

成片复制前按已编码文件的实际大小检查目标目录所在卷的可用空间，包括目录链接/junction 的真实目标。明确空间不足时不创建发布副本，编码与检查点保留；腾出空间后可继续。预检不预留磁盘空间，其他程序同时写入或系统配额仍可能让复制失败，原有校验和恢复不会因此省略。

## 输入与输出整理

Studio 自动新建的任务按 `字幕任务/YYYY-MM-DD/HHMMSS_视频名-短标识/` 分组，同秒创建会追加编号。指定输出目录时尊重所选路径；旧任务仍在原目录续跑。输入视频保留原位置，不复制大文件。工作台显示输入、任务、版本导出及已导出成片的位置；创建时间只有已知时才显示。

在结果区点击“保存字幕版本”，会把当前整片或所选样片的已有 SRT 复制到 `项目/导出/YYYYMMDD_HHMMSS_片段名/`，重复保存生成独立版本。每版包含 `输入来源.json`、`版本记录.json`，记录素材位置、片段偏移、文件哈希和审核状态。运行中的任务需先停止再保存，以免混入不同批次。样片 SRT 保持样片时间轴，原片偏移记录在版本说明中；版本保存不代表整片完成或已人工校对。

浏览器下载文件名包含视频名、片段名、语言类别和字幕修改时间；本机保存的版本使用保存时间。内部 `原文.srt`、按目标语言命名的译文草稿及 `双语草稿.srt` 保持稳定，人工修改与断点续跑不受文件整理影响。现有压制视频仍导出到原视频旁，界面提供“打开成片目录”。

## 停止与继续

准备素材、开始样片和整片处理时，源文件身份核对、音频缓存扫描及媒体时长探测也响应停止；探测子进程确认退出后才返回。恢复准备任务时，已保存完整音频只扫描一次，仍核对完整内容哈希。新提取音频在时长和哈希检查通过后才替换正式文件；取消或校验失败保留旧音频与待检查的 partial。准备的最后一次字幕写入或对照页生成期间停止，也不会再报告“准备完成”。本地识别入口保持原有 `cancelled` 返回状态，不把准备取消显示为运行故障。

样片预览的编码退出成功后，还会核对有效音视频轨、尺寸和时长，检查实际解码首帧起点，分别完整解码画面与音频并检查各自覆盖范围，再保存完整内容哈希和验证记录。空容器、只有末尾一帧但音频很长、空音轨或截断结果不会发布为准备完成；检查或停止失败保留已有预览与 partial，不因为验收失败自动换编码器重试。旧预览第一次继续准备时补做本地检查，不重新编码；验证记录绑定当前文件哈希和样片时长，之后恢复不重复解码。缺少有效预览证明时，样片识别和验收提示先继续准备，未提交付费请求。媒体验证只证明文件可用，不代表字幕内容已人工审核。

已检查的预览在保存时遇到 Windows 短暂文件占用，会有限重试同一次移动，最多6次，等待期间仍可停止；持续占用时保留原错误与 partial。保存采用不覆盖操作，编码期间新出现的目标文件也会保留。没有既有预览哈希绑定、且目标与 partial 内容不同的恢复任务会提示来源冲突，保留两份供核对，不自动接纳竞争目标。移动后重新核对完整哈希和文件状态，再写验证记录；此时取消，已移动的预览可以保留，但不会登记完成证明。再次准备会本地补验这个预览，无需重新编码。尚未移动的 partial 没有跨重启复用承诺。

继续任务时使用原项目目录和原处理模式。已保存的片段与原始服务响应会用于恢复；更换素材、识别引擎或参数时应创建新项目。人工改动会被核对和保留，存在冲突时会提示处理。

任务已收到停止信号时，先合并并保存已返回的片段结果，再登记“已停止”；跳过仅用于判断全部完成的重复片段校验。重新继续时仍按原规则核验缓存，未停止的任务仍完整检查识别与译文。已经开始的最终校验暂沿用原收尾方式。

收尾合并或保存失败时，保留已完成片段、人工字幕与恢复记录，并尽可能保存具体失败阶段；无法保存诊断时仍报告原错误。收尾和项目锁清理的次要错误不会替代最初的任务错误。进度通知失败与状态文件保存失败分别记录，不自动重复通知、合并或云端请求。继续成功后清除旧收尾诊断。

调度发生普通异常时，在已启动的处理线程退出后，程序会核验仍持有的成功片段结果，再登记和保存。只接纳来源、实际文件、字幕数量与时间轴都匹配的结果；公开字幕被人工修改时保留文件并提示核对，不覆盖修改。已登记的片段不重放，也不因此新增识别或翻译请求。此次调度仍显示未完成，下一次正常继续才判断全部完成；取消、失败或缺少证明的结果不能仅凭文件存在就算完成。

底层文件锁在解锁或关闭报错后，仍会尝试释放本机互斥锁，并保留具体路径和原始错误；无法确认操作系统锁已释放时继续报告失败。项目锁取得失败时，后续普通释放错误作为附加诊断，不盖过最初的取得失败。不会删除稳定锁文件或更换请求身份。

千问任务先核验已完成片段，再决定是否准备整片音频。识别已完成、只需继续翻译或合并时，不再要求或重新生成 `timeline.wav`；确有待识别片段时才准备一次。原始素材、识别来源、人工修改和费用账本仍按原规则核验，音频准备中断后保留检查点继续。

千问流水线在新增费用预留或发送识别请求前，还会检查已绑定的整段 PCM 与当前切段计划的长度覆盖：读取 WAV 头和末帧，按精确样本数比较，允许最多 ±250 毫秒的尾部封装余量。超出时保留计划、音频与已有结果，提示长度差，不自动重切或猜测起点。这是范围保护，不证明源时间起点、音画对齐或字幕内容正确；250 毫秒也不是通用同步精度承诺。检查不重复扫描完整 PCM。

准备音频时，完整 SHA 校验前后必须观察到同一稳定文件；本次运行保存其文件标记，在片段提取和每次新提交的检查中核对。音频在校验后被同长度文件替换或改写时，会保留产物并阻止新请求。文件标记只用于发现变化，不能替代内容 SHA，也不保证抵抗刻意伪造全部文件元数据的修改；已保存原始回包仍按原身份本地恢复。标记不改变任务身份或付费请求 ID。

这项准入检查在单个请求锁内、共享账本锁外执行，之后重新核对预算；限流后再次发送前也重新检查。检查失败不会把本地问题记成已提交或结果未知，也不会新增费用预留；既有待提交预留保持。已收到或成功保存的原始回包直接本地转换，不要求重新通过新请求准入；结果未知的旧请求仍禁止自动重发。识别身份、请求 ID 与人工审核规则保持原有合同。

程序在替换合并字幕前保存恢复记录，异常退出后会核对已写入的文件，再继续缺失步骤。未变化的合并字幕和复核清单不重复写盘。Windows 短暂占用文件时，只有限重试同一个已保存临时文件的替换；持续失败仍会报告错误。

字幕合并、费用账本、翻译缓存、原始识别响应副本及计价异常标记，清理各自临时文件时也会有限重试 Windows 短暂占用。若保存和清理都失败，保留真正的保存错误，并附加待清理文件的准确路径；不批量删除临时文件。已经成功落盘并记账的响应用于本地恢复，不重新发送；无法确认安全落盘的请求继续保持“结果未知”和原预算预留。

Windows 的本地编码及媒体检查子进程在绑定后随直接父 Python 进程退出而回收，正常停止仍保留原停止结果及已保存文件。本机短片实测：强制结束父进程后，两个调用路径的 FFmpeg 都在 500 ms 内结束；已完成的两个编码检查点可由新进程恢复，重编码次数为 0。保护从绑定成功后开始，启动到绑定之间的短暂窗口仍存在；这些测试验证进程崩溃恢复，不代表断电持久性或远端请求撤回。

主服务启动的识别、翻译和导出 worker 也使用上述 Windows 退出保护。模拟任务实测，强制结束主服务后，worker 及其下一层子进程在 500 ms 内退出。正常关闭浏览器时，后台任务继续运行。输出或进度报告出错时仍等 worker 真正退出；若退出未确认，保留“运行中”和本轮停止标记，确认后才允许新任务。输出管道清理失败不会掩盖原任务错误。

多音轨视频导出会复制全部音轨，逐轨检查数量、顺序、内容摘要、编码、采样率、声道、语言和 default/forced 标记。源文件完全没有指定默认音轨时，本机 MP4 封装会将第一条设为默认；程序明确记录源文件与成片的实际标记和这一转换，已指定的默认音轨仍必须保持。多音轨采用独立的版本与验证记录；旧版仅保留第一轨的成片不会被自动认证或覆盖。单音轨的既有绑定与编码参数保持兼容，已完成的长片编码无需因此重做。识别音频仍沿用第一条音轨；此项修改不改变识别输入。不能写入 MP4 的源编码仍由 FFmpeg 报错，保留输入和已生成文件，不自动改成有损音频。

多音轨内容摘要使用一次读取取得全部轨道的有序结果：源文件、编码文件各扫描一次，不再为每条音轨重复读取文件。数量仍由独立媒体信息核对；缺失、多余、重复或乱序记录、取消和读取失败都会阻止发布，不退回逐轨重复尝试。已保存的有效音轨证明格式保持兼容。合成 AAC、MP3、ALAC、AC3、FLAC、PCM 的指定封装组合验证了摘要等价，这不是整片耗时保证。

分段编码仍是研究方案，尚未启用。固定帧率小样可保持时间轴，但当前通用秒数切段原型在可变帧率样本出现偏差、非零起点样本丢帧；保留现有单次压制和编码完成后的恢复方式。

音轨内容校验比较复制的压缩数据，不声称不同容器解码后的 PCM 文件逐字节相同。8 秒 MKV 合成小样转为 MP4 时，两轨压缩包摘要及音画相对起点保持一致，解码样本数增加 16 个（约 0.33 ms）；这种容器边界变化已另行记录，没有当作完全相同的 PCM 结果。

停止后的退出确认直接等待 Windows 原生进程句柄，避免 Python 缓存退出码过早显示结束、日志仍被占用。等待实际结束后读取真实退出码，原生等待失败仍保留原停止/运行错误并附加清理诊断；没有固定睡眠来掩盖占用。

界面运行记录 `studio.json` 在控制锁外保存，慢写入期间仍可设置停止信号和读取状态。保存由一个调用者顺序执行，只保留一个最新待写快照，避免积压和旧状态覆盖新项目；保存警告按结果顺序更新，自动关闭闲置后端前会等待保存结束。承担写入的调用者仍会等待自身磁盘操作；字幕检查点与费用账本继续使用各自原有的持久化流程。

命令行的 `samples`、`full`、`draft` 只有在全部计划片段完成时返回退出码 `0`；部分完成、取消或错误返回 `2`，已保存进度仍可继续。自动化脚本应同时检查退出码和项目状态，不应把进程退出视为字幕已完整生成。

## 大项目预览与状态读取

状态轮询、字幕预览和媒体/下载路径读取使用独立的项目快照，磁盘读取不占用任务控制锁，避免慢预览拖住停止和进度更新。请求结束前再次核对项目选择；切换项目（包括切走后再切回）时不返回旧请求的结果。状态轮询可重新读取一次，并在返回前刷新当前任务状态和操作按钮。

前端也按请求顺序和项目切换批次丢弃旧状态响应，避免较慢的轮询把新项目或进度覆盖回去。任务运行时每约 1.1 秒只读取内存进度，每约 4.5 秒重新读取完整状态；项目、操作变化或任务完成立即读完整状态。手动浏览字幕时按字幕 ID 保留当前位置，修改时间不会跳回列表顶部。未保存的校对输入在切换到设置或任务记录后仍保留关闭/刷新页面提醒，并尝试保存本机草稿；点击保存后才写入项目。

单句保存返回该句和严格修订回执，前端保留其余条目的对象及当前位置；旧版本、项目不匹配或迟到回执仍拒绝覆盖。长字幕的播放定位使用时间索引，重叠字幕保持原先第一条匹配规则，旧无 ID 字幕仍按位置重播。

首次建立本机会话、本地状态、进度和字幕预览的 JSON 读取使用 15 秒截止时间，环境检查为 30 秒，覆盖连接和响应正文；超时后解除等待，保留入口凭据供手动重新连接。保存、启动任务等业务写入请求和文件下载不套用此截止时间，不因读取超时自动重复提交。错误提示位于连接栏下方，保留“重新连接”按钮的点击区域。

字幕预览按文件内容复用解析结果，每次仍读取并校验实际内容，能识别保持大小及修改时间的手工编辑。缓存最多保留 12 份、合计 8 MiB 原文对应的解析结果及 50,000 条字幕；超过限制的文件照常读取，不长期缓存。文件损坏或无法读取会报错，不用旧缓存掩盖问题。此缓存仅加快预览，不作为识别完成或断点恢复的证据。

人工校对另有同样容量限制的基础条目缓存，绑定原文/译文内容、语言、素材身份、时长和复核清单。每次仍读取真实文件和人工记录、检查绑定冲突、校验人工修改与告警；不缓存整个校对结果或版本号。2026-10-04 本机 4,500 条合成字幕的 9 轮交错测量中，校对读取中位耗时约 73.0 → 28.8 ms，完整预览约 181.4 → 97.6 ms；仅说明该夹具在本机重复读取的收益。

启动、选择项目等写操作继续保留原有校验；此次优化不改变云端识别速度。已打开的后端进程需重新启动后才会加载代码修改，仅刷新网页不会更新后端。

运行中的状态消息最多保留 800 字符，日志最多 150 条、每条含时间最多 500 字符。敏感凭证先隐藏再截断，相邻重复的显示内容不反复追加，避免异常长输出持续扩大状态响应。
