# 导入字幕的消费字节绑定 Implementation Plan

**Goal:** 第 13 轮。关闭来源哈希与实际读取导入字幕之间的竞态，避免带旧 seed 身份的新内容被持久化并在下次错误复用。基线 `055e75f`，累计此前 12 轮；下一次反思在第 15 轮。

**Evidence:** `batch5/seed-audit.log` 已证明真实临时字幕在 `file_identity` 返回后被改写，任务仍 complete、保存旧哈希却生成新字幕；恢复原字幕后又 complete 复用错误结果。

**Design:** 保留现有稳定 `file_identity` 以及任务格式，导入字幕的第二次读取以有取消检查的块读取保留实际字节，并核对该字节集的大小/SHA，解析这同一字节集。核对及解析放在新状态/预算准备前。输入之后再变化，不影响已核对的内存快照；不额外做第三遍文件读取，不建立媒体快照框架。

**Constraints:** 保留旧 identity、mtime 兼容、人工文件、缓存、账本和停止语义。仅用临时合成文件与替代服务；无真实提供商。严格的哈希相等核对不能用时间戳或大小代替。

- [x] 新增修复前失败测试：哈希后改写/替换、读取中改写及恢复 mtime，不得产出带错身份的结果；正常 BOM/多行字幕与中途取消对照。
- [x] 在 runner 小范围实现实际消费字节核对，并用同一字节集解析；变化时拒绝，尚未创建/修改任务状态与付费数据。
- [x] 验证已读取后输入再次变化时，处理仍绑定原始快照；恢复原文件后只复用同一内容。核对读取次数、停止以及既有 seed/runner/云端离线专项。
- [x] 独立审查，冻结后完整后端/HTTP 验证，更新持续优化与验证报告：1,323 项后端（3 项权限 skip）、26 次回环请求，138 个源码/测试哈希未变。公开发布与 CI 回执另外保存。

公开内容扫描、推送、对应提交 CI 与主工作区同步的回执另存在忽略的 batch5/release-receipt.json，避免为写入自身发布结果重复提交。
