# 原文字幕校对设计

基线：`52f18099feba82849b0dac7fad14e868182512e7`。目标是让默认离线原文任务在应用内完成生成、纠错、逐句检查、下载与保存版本，减少外部工具切换；不需要开启翻译或调用提供商。此为第30轮候选，完成后进行五轮反思。

## 范围与兼容

- 扩展现有人工校对层、项目锁、稀疏修订、版本 CAS、不可变快照与保存回执；不复制一个平行校对系统，不增加依赖或提供商请求。
- 双语 v1 记录、默认记录、binding、JSON 字节、修订和四文件快照保持原样；既有验收与下载行为不变。不要加载时迁移或重写。
- 新原文记录使用 `version=2, mode=source_only, binding, patches`。只有明确 `state.config.translate is False` 且实际没有译文和双语轨，才建立新原文层；有效原文、身份、时长和来源摘要仍须验证。存在 v1 时优先沿用 v1 契约。损坏/缺译文的翻译任务不能降级；已有 v2 改模式或新增译文应保留并报冲突。
- 自动检测原音仅在新原文分支允许，旧双语语言校验不放宽。状态和轨集合决定模式，客户端不能声明模式。

## 持久化和接口

- 保持 `load_review(folder, *, language='ja', target='zh-CN')`、`save_review(folder, data, ...)`、`materialize_review(folder, ..., require_accepted=False)` 调用方式。
- v1 返回视图维持现有形状。v2 视图和物化回执增加 `mode='source_only'`、`acceptance_supported=False`。其 binding 明确包含原文模式、原身份/时长/语言、原文摘要、疑点摘要；建立前和保存/发布前均验证单轨资格。
- v2 patch 仅含 `start_ms,end_ms,source_text,review_status,note`，不保存假译文或 `translation_stale`。展示 cue 可保持 `target_text=''`、`translation_stale=False` 以兼容现有草稿/回执。
- 保存请求沿用完整字段格式，但 v2 严格要求 `target_text==''`、`translation_confirmed is False`；拒绝隐藏的译文输入，保留调用者草稿。原文和时间验证、显式 checked、疑点备注规则、CAS 和提交前底稿复核保留。普通内容变化清除旧检查状态。
- v2 summary 统计检查/疑点，`pending_translation=0,can_accept=False`；检查全部原文不代表双语最终验收。
- v2 物化仅含 `原文.srt` 和原始 `校对记录.json`，继续按修订发布和核对精确文件集；`require_accepted=True` 显式拒绝。旧文件和机器字幕不改写。
- Studio 预览、完整及紧凑单句回执、物化下载和保存版本，必须传递同一模式及修订。版本清单只包含真实可用原文轨；译文/双语下载明确失败，不回退到机器旧文件。

## 使用流程

- 本地原文结果出现现有逐句编辑入口，可修改原文、起止时间、备注和检查状态，可“核对并下一条”，保留原保存/重连/跨窗口保护。
- 隐藏原文模式的译文编辑、译文确认、待译文统计及整片验收；语言标记显示“英语 · 原文字幕”等，不显示不存在的翻译方向。
- 旧双语草稿若在原文模式下仍含译文或确认标记，显示可复制的恢复草稿并阻止提交；不静默清空或藏起输入。
- 隐藏原文模式不可达的云端最终验收及 MP4 操作引导，明确当前可交付原文字幕。原文 MP4 导出是后续候选，本轮不实现，也不称完整视频交付已支持。
- 原文任务完成及采用外部原文修改时，提示原文保存/复核，不声称存在新译文或已备份不存在的译文；双语提示保留。

## 验收

1. v1 固定基线字节/修订和快照兼容；加载不写盘。
2. v2 编辑、时间、备注、checked、CAS、重启、下载和保存版本闭环；机器字节不变，无译文产物、无提供商请求。
3. 缺/坏译文、未知配置、已有缓存译文、模式切换、记录损坏、底稿变化、路径联接及发布失败边界保持明确失败/冲突。
4. 前端保存/下一条/草稿恢复/紧凑回执持续保持原文模式；不出现不可达的验收/翻译操作，旧双语交互回归。
5. 完整后端、前端、HTTP、构建、冻结摘要和独立审查通过；实际浏览器在合成原文项目中编辑、切页接续、下载及保存版本一致；未触碰真实项目、预算或凭据。
