# 字幕工坊下一轮优化设计

用户已要求落实此前提出的全部五项优化。本轮目标是保护校对劳动、改善长字幕响应、扩大本机导出兼容性，并降低维护成本。

## 行为与边界

1. 校对草稿按项目、片段、字幕 ID、基准修订号保存本地；刷新后恢复，版本变更显示冲突。草稿不自动成为正式字幕。只存校对字段，凭据和启动令牌不写入浏览器存储。存储损坏或空间不足不阻止编辑、正式保存；设置容量和保留时间上限。
2. 保存单句返回小回执（项目、片段、原修订、新修订、该句、汇总）；客户端仅在匹配基准版本时应用。迟到回执、跨布局提交、保存后的新增编辑及跨窗口冲突保持原行为。普通全量预览仍可显式刷新。播放位置查找复用索引，保留重叠字幕及无稳定 ID 的兼容行为。
3. 提供可手动刷新的环境自检：Python/Tk、FFmpeg、ffprobe、libass、Whisper 模型、QSV 实际可用性和 CPU 编码器。检查不发送模型请求；调用外部进程有期限。整片导出支持 auto/qsv/cpu，auto 优先可用 QSV，其次 CPU；显式选择失败应清楚报告。编码方式进入检查点身份，保留既有 QSV 结果兼容性及严格源/字幕/音轨校验。
4. 建立可复用的本机媒体验收工具，使用合成媒体覆盖浏览器预览、时间跳转、字幕压制、多音轨、取消及恢复。记录实际环境、检查结果与人工听看边界，不声称短片能证明任意长片或云端质量。
5. 从 cloud_workflow 拆出媒体导出职责，保留现有调用入口和记录格式；在此边界承载编码选择与恢复逻辑，避免影响识别、费用及人工验收。

## 验收

每项先建立故障/新行为测试并确认失败，再实现。最终执行完整后端、HTTP/DPAPI、前端与构建一致性检查；测量 5,000/20,000 句保存响应体及耗时，真实 FFmpeg 合成媒体导出、取消恢复，并实际检查浏览器操作。源工作区和个人素材保持可追溯，新工作在独立管理 worktree 中完成。验证后按已有 GitHub 发布授权提交并更新公开仓库，检查远端 CI。
