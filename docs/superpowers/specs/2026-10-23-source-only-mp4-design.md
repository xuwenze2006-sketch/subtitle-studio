# 原文 MP4 导出设计

基线 `03be4e06018ff63125b1e1d88ab4228bfe64eb35`。用户要求优先补齐原文 MP4，验证后上传现有公开 GitHub。完成原文生成→校对→字幕压制视频，减少外部工具操作，不调用提供商、不修改真实项目/凭据/费用。此为第31轮；下次五轮反思仍为35。

## 方案

复用 `media_export` 已有编码、ASS 转换、进度、编码器选择、全部音轨校验、解码检查、完整性摘要、检查点和安全发布；将既有双语输入校验与共享渲染分开。新增本地原文输入/回执模块 `source_video_export.py`，不伪造云端 campaign 或最终验收。

现有 `export-draft` 操作继续通用。Studio 对合格本地原文项目启动独立模块 worker；云端命令及 v1 绑定/快照不变。主界面与校对页通过明确 `source_export_supported` 展示原文草稿 MP4，继续使用现有播放、目录、认证下载和停止入口。

## 输入和安全边界

- 只接纳无 campaign 的本地 Whisper 项目，配置明确关闭翻译，source/project、语言、时长、来源身份一致，状态完整，没有待发布/待合并冲突。自动检测原音可用。现有 v2 原文校对资格继续权威，译文轨或 v1 双语记录不降级。
- 可用性检查只读、不运行 FFmpeg/模型。实际导出持有项目锁及原视频全程稳定读保护，重新哈希素材并验证全部片段来源/内容证据和分段计划；完整性不靠 `status=complete` 一个字段。
- 当前有效的原文 SRT 是交付输入，不能只因它与旧 generated_hashes 不同就覆盖或丢弃合法外部人工修改；待处理的生成日志/冲突仍须拒绝。使用 v2 物化快照，绑定当前字幕摘要、来源、状态/生成证明、语言、修订和实际记录是否存在。
- 已知导出证据要求人工记录时，记录丢失必须报告，不能悄悄回退到机器原文；包括空 patch。提交前、媒体发布/登记前重新核对当前字幕与状态，底稿变化时保留结果但不登记为当前成功。
- 路径固定且包含性校验，拒绝符号链接/目录联接。失败、取消、同名异物和文件占用保留原文件；不覆盖未知文件或删除历史成片。

## 输出和恢复

`导出/原文视频/` 保存明确带“原文”“未审核草稿”和稳定输入键的视频名；每个输入键拥有独立工作目录。键由未选编码器前的输入绑定及请求编码方式确定，改变保存修订生成独立版本，不要求用户先挪走旧版。同一绑定和编码方式在摘要及媒体证明吻合时复用既有结果/编码检查点。

单独 `export.json` 回执记录当前原文视频位置、SHA-256、绑定和实际编码器，不改变流水线完成/人工验收状态。只暴露与当前来源、底稿、人工修订、实际记录存在性和视频摘要相符的文件；编辑后旧文件保留但入口撤下，返回原修订时可从原检查点恢复。与 MP4 不兼容的音频编码直接报错，不自动有损转码。

每个输入键保存独立回执，顶层回执原子指向当前版本；顶层写入失败可以从确定的输入键恢复。固定 `ownership.json` 记录已经验证出现过的实际人工记录，绑定来源且只会保留“见过人工记录”的事实，不能因删除顶层回执而退回机器版本。不通过遍历目录时间推断历史；所有相关所有权证据均被外部删除时无法推断已丢失历史。

前端原文模式仅 `source_export_supported===true` 才开放 MP4；旧响应继续隐藏。未保存、保存等待、恢复草稿冲突、项目/修订冲突和任务运行时禁止新导出，保存成功后再刷新能力/成片入口。原文仍不出现译文确认/整片双语验收，不因导出获得审核状态。播放不自动发生，下载使用认证路由。

单句紧凑保存回执直接提供同名能力布尔值，消费回执时更新能力并清除旧成片，不为保存增加整份预览 GET；原文回执缺少新能力则保守撤下入口，等待正常刷新。已应用的新修订预览继续遵循原回执校验，不能被迟到旧回执覆盖。

## 公共接口

- `source_export_available(project, source) -> bool`：只读且廉价；完整工作验证仍由导出执行。
- `export_source_video(project, stop, *, encoder='auto', emit=None)`：完整保护、输入验证、共享渲染、回执和进度。
- `current_source_video(project, source, *, video_matches) -> Path | None`：只读核对当前入口，可使用 Studio 现有强文件代次摘要缓存；实际导出永远重新核验来源。
- `python -m subtitle_pipeline.source_video_export --project <path> --encoder auto|qsv|cpu`：JSON 行进度，沿用 `SUBTITLE_STUDIO_STOP_FILE`，父进程退出保护继续有效。
- 共享渲染函数具体参数由 backend 实施定义，必须保持旧云端调用/编码绑定/文件路径及测试行为不变。

## 验收

新增 RED→GREEN 覆盖原文与人工修订压制、全部音轨、无译文/无提供商、重复导出不编码、修改后新版本、缓存/源文件/字幕/记录损坏与删除、取消/失败后安全恢复、路径逃逸/链接。Studio 覆盖动作资格、正确独立命令、停止/进度、状态重启、旧片入口撤下和认证下载。前端覆盖两布局、忙碌/草稿/冲突禁止、进度及结果，并保持旧双语交互。

完整后端、前端、HTTP、生产构建和独立最终审查通过后，真实 FFmpeg 合成多音轨视频，实际浏览器启动原文导出，核对视频时长/帧数/分辨率、各音轨压缩数据、烧录字幕画面、下载和重启缓存复用；输入及机器字幕不变。公开允许路径扫描、普通推送、同提交 CI 全成功、干净主目录快进同步。合成素材证据不冒称真实长片/GPU/原生桌面验收。
